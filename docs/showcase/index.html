THE CODE THAT RUNS HERE
A small boundary between events and pixels.
Start with integration.mjs: mount, allowlist, handle events, publish data, dispose. These are the actual source files embedded during the asset build, not illustrative copies. Install @veil-runtime/ui@0.4.2 and bundle these modules in a browser application with a mount element.

        

        
To connect a real agent, replace the simulator with your host’s event adapter. Validate incoming events, maintain run identity, and enforce authorization on the server before performing side effects. Keep the UI-facing event and update boundary.

      

      

        
RESPONSIBILITY, MADE VISIBLE
The host runs the work. UI makes it usable.

        
  1. 01 / HOST
    Produce events
    A deterministic timer emits simulated tool results. Run and pending-work identities invalidate late callbacks.
  2. 02 / HOST
    Project state
    The host checks lifecycle transitions and maps its model into bounded steps, status and timeline data.
  3. 03 / VEIL UI
    Render updates
    updateData(data, revision) validates the candidate. Built-in components render accepted values as text and reconcile the DOM.
  4. 04 / HOST
    Handle decisions
    Veil UI emits an allowlisted action with source, state and revision. The host checks the current phase before accepting approval or cancellation.

        
Veil UI owns
Descriptor validation, state bindings, conditional controls, action dispatch, revision checks, snapshots and DOM mounting.
Your application owns
Agent execution, event validation, transport, identity, authorization, tool policy, scheduling, retries, cancellation and external effects. A disabled button is not a security boundary.
Safe by construction
No network requests, credentials, custom renderer code from visitors, or executable HTML. Host actions are allowlisted and phase-checked. Timeline length is bounded. Reset and disposal invalidate pending work.
Preparation errors preserve the accepted interface. Renderer commit failures cannot promise DOM rollback or undo external effects.

        
Browser module bundling is required. The package declares Node ≥24 for tooling; its optional Core peer is ^0.4.0. This example uses no Core and makes no Core 0.6.0 compatibility claim.
