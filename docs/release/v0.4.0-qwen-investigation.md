# Local Qwen write-planning investigation

Observed 2026-10-24 on Linux x86_64/WSL2, Node v24.18.1, Ollama 0.32.14,
`qwen3:0.6b` (installed ID prefix `7df6b6e09427`). This is release evidence for
the optional source-server planner, not a model quality guarantee or npm API.

## Reproduce

With the existing model served on loopback port 11434:

```bash
npm ci
npm test
node tools/diagnose-local-planner.cjs
```

The diagnostic registers only synthetic `fixture.echo` and `fixture.write`
capabilities in its own process. It uses the actual compiled adapter and runtime,
30-second call deadlines and the adapter's 1,024-token request. It captures the
serialized request in memory to replay the same messages against Ollama's native
and OpenAI-compatible streaming endpoints. It prints timing, character counts,
capability names and outcome metadata, not reasoning text or repository data.
No model is installed, no inference service is started, no retry or paid endpoint
is used and no filesystem write capability is provided. The write fixture throws
if invoked; its invocation counter remains zero. Diagnostic exit 1 preserves
provider/runtime expectation failures; native probes are observations only.

## Actual observations

| Probe | Observed result |
| --- | --- |
| Actual adapter, exact-value read | Completed in 7,136 ms; `fixture.echo` returned the exact synthetic value. |
| Actual adapter, original write wording | Returned `fixture.echo` in 6,734 ms; expected-write assertion fails. The selected read is allowed; this is a wrong model proposal, not authorization bypass. |
| Native streaming, same original messages, default thinking | First bytes 260 ms; completed 5,619 ms; 874 thinking characters, 92 content characters; still selected `fixture.echo`. |
| Native streaming, same messages, explicit `think:false` | First bytes 375 ms; completed 753 ms; zero thinking characters, 77 content characters; still selected `fixture.echo`. |
| Actual adapter, explicit write wording plus `/no_think` | `Planner request timed out` after 30,008 ms; no execution for that proposal. |
| Direct OpenAI streaming replay of the explicit write request | First bytes 765 ms; streamed 974 reasoning and 902 content characters; still incomplete at the independent 30,016 ms timeout. |
| Native streaming, explicit write messages, `think:false` | First bytes 689 ms; completed 1,728 ms; zero thinking characters; proposed two steps, `fixture.echo` then `fixture.write`, contrary to the requested single write. This raw diagnostic proposal was not executed. |

Final counts: two read fixture executions, zero write executions, two failed
provider/runtime expectations. Combined diagnostic exit 1. Earlier repetitions
also selected the wrong read, and reproduced the explicit-write timeout at
30,019 ms. The exact timings vary; no timing threshold is a release test.
Machine-readable observations and the final log hash are retained in
[the release evidence](v0.4.0-evidence.json).

## Cause and disposition

The reproduced timeout is spent in inference/generation. Direct streaming reaches
the server promptly and continues receiving model output, independently of Veil's
non-streaming adapter and runtime. The adapter's deadline fires on time; there is
no observed execution deadlock, HTTP outage, missing model or wrong endpoint.
Native no-thinking control substantially reduces generation time, but does not
correct capability/step selection. Natural-language "Do not think" and a
`/no_think` marker inside JSON goal data did not reliably control this host/model's
thinking behavior through its OpenAI-compatible JSON response mode.

This supports a model/prompt behavior and thinking-configuration diagnosis for the
reproduction. It does not distinguish every internal Ollama/Qwen JSON-generation
interaction. The uninstrumented October 23 timeout cannot be assigned an exact
historical cause. Host contention/cold loading were not independently controlled;
this is not a model throughput benchmark. Observed native load durations were
about 155–285 ms in the final run, far below the reproduced deadline.

No timeout increase, automatic retry, authority relaxation, model substitution or
Qwen-specific wire parameter was added to the generic adapter. A prompt-only
change failed to establish reliable proposals, so it was not promoted as a fix.
`think:false` on the native endpoint is an investigation control, not a supported
new adapter option. Existing mocked regressions prove that a valid proposed write
passes admission to default denial and never starts, independently of model quality.
The combined live write acceptance remains failed. Deterministic routing and
application-owned planners remain available without local inference.

Ollama documents [thinking controls](https://docs.ollama.com/capabilities/thinking)
and its [OpenAI compatibility subset](https://docs.ollama.com/api/openai-compatibility).
The measured behavior of the installed server/model takes precedence over assuming
that a prompt phrase or newer protocol feature disables thinking.
