## Supported scope

Linux is the currently supported execution platform. Qualification ran on Linux
x86_64/WSL2, kernel 6.18.54.1, Node 24.18.1, npm 11.16.0. Windows and macOS are
**unqualified**, with no native security/execution claim. Native results are needed
before extending that scope; they do not block this Linux-only release.

Core remains independently usable without a model. UI and Emergence are separate
packages. Sandbox, repository-task, browser providers, Caretaker and experiments
are not added to Core's public API/artifact. ExecutionPlan V1 remains the default;
V2 remains host opt-in. Public job/result/event contracts and authority boundaries
are unchanged. Sole root export and package exclusions are verified.

Local model planning is experimental, opt-in source-server infrastructure.
`OPERATOR_LOCAL_PLANNERS=1` and explicit planner selection are required. Wrong
capability selection, extra steps and write-generation timeouts remain recorded in
[v0.4.0-qwen-investigation.md](v0.4.0-qwen-investigation.md). No reliable autonomous
write-planning claim is made. Those optional model probes are not the deterministic
Core acceptance criterion; their failures have not been relabelled as passes.

## Remaining limits and independent work

No mandatory Linux Core blocker remains in the recorded gates. Host-trusted roots,
ancestors, mount namespace and procfs are required for the source filesystem
provider. Network filesystems, host compromise, atomic content snapshots, aggregate
resource/concurrency quotas, general capability cancellation, tenant authentication
and browser SSRF policy are outside its guarantees. Windows/macOS portable checks
still require quiescent directories and do not promise race-free confinement.

The capability branch has eight vulnerable dependency entries and source-coupled
applications despite passing sandbox/task tests. Those blockers do not change Core's
clean lock or justify including the applications in Core. See the
[independent assessment](independent-capabilities-2026-10-25.md).

The full initial inventory, clean worktree states, branches/tags, before/after
remote refs and secret-review disposition are in
[preservation-2026-10-25.json](preservation-2026-10-25.json).
All initially local workstreams are now remotely reachable; no experimental ref
was deleted. `develop` remains behind its remote ancestor and was not overwritten.
The verified full-history bundle is `/tmp/veil-preserved-2026-10-25.bundle`.

## Exact publication procedure — not executed

Registry inspection on 2026-10-25 found versions through 0.3.1; 0.4.0 was absent.
After maintainer approval, use the final committed candidate and rerun gates if
source, package metadata or dependency locks change. Inspect quality exit 1 against
the four accepted controls above; never suppress it or select a more convenient base.

```sh
git switch release/core-v0.4.0
npm ci
npm run check
npm run test:quality
npm run quality -- --base v0.3.1
npm audit --json
jekyll build --source docs --destination /tmp/veil-core-release-site --baseurl /veil --strict_front_matter
python3 tools/verify-rendered-documentation.py /tmp/veil-core-release-site /veil
mkdir -p /tmp/veil-core-release-artifacts
npm pack --json --pack-destination /tmp/veil-core-release-artifacts
npm publish /tmp/veil-core-release-artifacts/veil-runtime-core-0.4.0.tgz --access public --tag latest
```

If that branch is attached to the retained worktree, run there instead of switching
another worktree. The `npm publish` line requires publication approval and npm
credentials/2FA. Install and verify the exact retained tarball in an independent
consumer before publishing any newly generated replacement. Artifact hashes and
consumer evidence for this run are recorded in the qualification JSON.

Publication order: Linux Core 0.4.0 first; separately qualified sandbox preview;
repository host preview after public-Core integration; experimental live adapters
and browser infrastructure only after their own blockers are resolved. UI and
Emergence follow their independent package qualifications. No independent package
is presently ready for an npm publication command.
