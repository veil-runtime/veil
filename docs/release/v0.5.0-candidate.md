Status: **unpublished integration candidate**. The latest published Core release is v0.4.0. This candidate retains the sole package-root export and the existing ExecutionPlan, OperatorRuntime, Capability, job, result and event contracts. Core, UI, Emergence and future Sandbox are independently versioned.

## Consumer use and compatibility

Until publication, install the exact candidate tarball from the release qualification record, not `@veil-runtime/core@0.5.0` from npm. The package requires Node >=24. Linux is the qualified execution platform, based on Linux x86_64/WSL2 and Node 24. Windows and macOS filesystem tests run in CI, but complete native platform qualification has not been established. No model or UI is required. V1 remains the default plan version; V2 requires host opt-in.

Applications should import only from `@veil-runtime/core`, define capabilities, register a module, and call `executePlan`. The default authorizer allows reads and denies writes/destructive work. The source development server is loopback and unauthenticated, not a production network service.

Core does not promise cancellation, retries, exactly-once effects, runtime-wide budgets, tenant isolation, durable event delivery or autonomous write planning. Registries and job services remain process-global. The local model adapter is experimental and opt-in; its historical live write-planning failure is not treated as passing evidence.
