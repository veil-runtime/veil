# v0.1.0 Release Work

The architecture is locked at tag `v0.1.0-arch-lock`. Release work may package,
test, document, and demonstrate those contracts; it must not redesign them.

## Critical path

- [x] Architecture lock and execution-contract tests.
- [x] Public root entry point and npm package metadata.
- [x] Packed-artifact allowlist and private-subpath boundary.
- [x] Consumer typecheck/runtime fixture and negative import verification.
- [x] Replace the platform-fragile test loader with compiled native Node tests.
- [x] Audit README examples and verify the public API example through the fixture.
- [x] Run `npm ci` and `npm run check` in a clean Node 24 Linux container.
- [x] Audit license, repository, engine, export, and publication metadata.
- [x] Inspect the dry-run package contents and exclusions.

## Human-controlled release actions

- [ ] Commit the release-readiness changes.
- [ ] Open a pull request from `develop` and allow the pull-request CI to complete.
- [ ] Merge the reviewed pull request to `main`; pushes to `main` run CI again.
- [ ] Create and push annotated tag `v0.1.0`.
- [ ] Create the GitHub release.
- [ ] Publish `@veil-runtime/core@0.1.0` to npm.
- [ ] Verify the package from the public npm registry.

## Agent ownership

1. `package-release`: package metadata, exports, fixtures, and pack validation.
2. `contract-tests`: focused positive and negative contract coverage.
3. `examples`: public-API-only examples and matching documentation.
4. `release-review`: read-only final diff and readiness audit.

Only one agent may own `package.json` or `src/index.ts` at a time. Architecture
and public-contract changes remain maintainer decisions.
