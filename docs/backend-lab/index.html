Minimal integration
npm install @veil-runtime/ui@0.4.2
import { createMountedInterface } from '@veil-runtime/ui/dom';
const definition = { id:'records', actions:['search'], state:{ query:'' },
 screen:{ key:'root', component:'Stack', children:[
  { key:'query', component:'Input', label:'Search', binding:{ source:'state', path:'query' } },
  { key:'search', component:'Button', text:'Search', action:'search' },
  { key:'records', component:'List', binding:{ source:'data', path:'records' } } ] }, data:{ records:[] } };
let ui;
ui = createMountedInterface(document.querySelector('#app'), definition, {
 allowedActions:['search'], onEvent: async event => {
  if (event.action !== 'search') return;
  const response = await fetch('/api/records?q=' + encodeURIComponent(event.state.query));
  if (!response.ok) throw new Error('Request failed');
  ui.updateData({ records: (await response.json()).records }, event.revision);
 }
});
// On teardown: ui.dispose();
Production hosts must validate server inputs, authenticate and authorize every write, cap request/response bytes, and handle cancellation and overlapping requests. A client action allowlist is not backend authorization.


Request and response path
  1. HOST
    Capture intent
    Veil UI validates fields and emits an allowlisted action.
  2. HOST
    Send HTTP
    The host adapter uses fetch, AbortController and monotonically increasing request identity.
  3. BACKEND
    Enforce policy
    Node service checks same-origin, session cookie, body byte limit, exact fields and server-side field constraints.
  4. HOST → VEIL UI
    Accept current response
    The host ignores aborted or superseded responses and applies current data with the expected UI revision.
The local sample uses an HTTP-only same-site demo session. It is learning code, not production identity infrastructure. The Pages simulation makes no network request.
